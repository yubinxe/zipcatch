## ⑥ 후속 백로그 (중요도 순)

1. **[높음] 기존 견줌자의 실패=0건 문제** — `molit-trade.ts`·`molit-rent.ts` 를 `flow-core` 의 `parsePage`·페이지 읽기로 옮겨, 모든 달이 실패하면 '거래 없음' 대신 '불러오지 못함'을 띄운다. 공고 상세 문구가 바뀌므로 별도 PR.
2. **[높음] Preview 실데이터 검증** — 위 미검증 3건. 결과에 따라 필드 이름·코드표 보정.
3. **[중간] 지역 간 비교** — 두 시·군·구를 같은 조건으로 나란히(같은 API, 캐시 재사용).
4. **[중간] 출처 상태 기록** — 달별 성공/실패와 응답 시각을 이미 계산한다. 이를 루틴 결과(`routines.ts`)와 같은 자리에 남기면 운영 점검의 근거가 된다.
5. **[중간] n8n 운영 점검** — 하루 한 번 대표 시·군·구 몇 곳의 `/api/market/flow` 상태(`ok/partial/error`)와 `/api/cron/routines` 결과만 읽어, **실패·부분 실패일 때만** 분석 단계를 부른다. 같은 실거래를 매일 다시 요약시키지 않는다. (n8n 워크플로는 이 저장소 밖 — 설계만)
6. **[중간] AI 보고서(Hermes)** — 입력은 `/api/market/flow` 응답 그대로(조건·표본·월별 분포·앞뒤 비교·품질·출처·조회 시각). 출력은 사실/가설/한계를 칸으로 나누고, 숫자는 입력에 있는 것만 인용하게 검증한다. Hermes 의 실제 인터페이스는 이 세션에서 확인하지 못했으므로 연결 코드는 쓰지 않았다.
7. **[낮음] Atelier AX 이벤트** — `DATA_CHECK_STARTED → … → RUN_COMPLETED` 를 공통 run_id 로. Atelier 저장소의 기존 브리지 스키마를 먼저 읽어야 하며, 이번 세션에서는 그 저장소를 열지 않았다.

## ⑦ 포트폴리오용 요약

> KREMA 「AI 자동화·바이브코딩 부동산 실무」 세미나 이후, 운영 중인 청약·공공임대 서비스 집캐치에 국토교통부 실거래가 공개 API 기반의 **지역 실거래 흐름** 기능을 설계·구현했다. 전국 256개 시·군·구 × 매매·전세·월세 × 3개 주택 유형을 월별 중앙값·사분위·표본 수로 보여 주고, 청약 공고 상세에서 같은 지역의 흐름으로 바로 잇는다. 해제 거래 제외, 불러오기 실패와 0건의 구분, 신고 기한이 남은 달 표시, 3건 미만 대푯값 비공개를 코드와 단위테스트로 강제해 **데이터가 말할 수 있는 것만 말하게** 했다.

(처리 시간·비용 절감 같은 수치는 측정하지 않았으므로 적지 않는다.)
